# 성능 개선 보고서 작성

> 요약: 성능 개선 전후 기록으로 문제 → 원인 → 변경 → 결과 → 한계 보고서를 쓴다

## 절대 규칙
- **숫자는 기록에서만 가져온다.** k6 결과 비교는 `scripts/k6_compare.py`가 계산한 값을 그대로 옮긴다. 직접 계산하거나 반올림을 바꾸지 않는다.
- **없는 측정을 만들지 않는다.** 기록이 없는 항목은 "측정 안 함"으로 적는다. 부하 테스트를 새로 실행하지 않는다 (필요하면 사람에게 요청).
- **조건이 다른 두 측정을 전후 비교로 쓰지 않는다.** VU, 시간, 데이터, 환경이 다르면 그 사실을 "한계"에 적고, 비교 가능한 것만 표에 넣는다.

## 1. 기록 모으기
- 사람이 알려 준 증거 폴더, 또는 프로젝트 `AGENTS.md`에 적힌 증거 위치(예: `docs/evidence/`)를 읽는다.
- 찾을 것: 개선 전·후 k6 결과(`--summary-export` JSON), 실행 조건(스크립트, VU, 시간), 지표 기록(커넥션 풀, DB, GC 등), 스레드 덤프·JFR 요약, 관련 커밋(`git log`, `git show --stat`).
- 원인 분석 기록(이슈, 분석 메모)이 있으면 원인 설명의 근거로 쓴다.

## 2. 전후 비교 계산
스크립트는 이 SKILL.md가 있는 폴더의 `scripts/` 안에 있다. `cd` 없이 **전체 경로로 하나씩** 실행한다 (명령을 `&&`로 묶거나 변수에 담지 않는다).
```bash
python3 /…/scripts/k6_compare.py <before.json> <after.json> --name <측정 태그 이름>
```
- 측정 태그 이름은 k6 스크립트의 `tags: { name: … }` 값이다. 모르면 `--name` 없이 돌리면 있는 지표 목록을 보여 준다.
- 지표 기록(커넥션 대기 등)은 파일에 적힌 값을 그대로 옮긴다.

## 3. 보고서 쓰기
`references/report-template.md`의 형식을 따른다. 요점:
- **요약 한 줄**: 무엇을 바꿔서 핵심 지표가 얼마에서 얼마로 바뀌었는지
- **문제**: 증상과 그때의 숫자
- **원인**: 근거(지표·덤프·쿼리)와 함께. 정상 구간과 이상 구간의 차이를 설명하는지 확인한다
- **변경**: 무엇을 왜 바꿨는지, 관련 커밋·파일
- **결과**: 전후 표 (같은 조건임을 표 위에 밝힘)
- **한계**: 측정 환경(로컬·단일 장비 등), 반복 횟수, 보지 않은 것, 남은 위험
- 사람이 저장 위치를 정했으면 그 파일로 쓰고, 아니면 프로젝트 관례(예: `docs/perf/`)를 따르거나 답변으로만 준다.

## 4. 완료 후
- 만든 파일 경로와 요약 한 줄을 알려 준다.
- 숫자를 어느 파일에서 가져왔는지 출처를 보고서에 남겼는지 확인한다.
