# 연락처 DB 점검

## 절대 규칙
- **원본 파일을 고치지 않는다.** 문제 목록과 수정 제안만 만든다. 합치기·삭제는 사람이 확인한 뒤 한다.
- **판정은 스크립트가 한다.** 중복·형식 판단을 눈으로 하지 않고 `scripts/check_contacts.py` 결과를 옮긴다.
- 연락처는 개인정보다. 점검 결과에 필요한 만큼만 적고, 파일을 외부로 보내거나 업로드하지 않는다.

## 1. 기준 확인
- 업무용 `AGENTS.md`에서 DB 칸 구성, 필수 칸, 중복 기준, 정보 유효 기간을 찾는다. 없으면 기본값(필수: 회사명·이메일·출처, 90일)을 쓰고 결과에 밝힌다.
- 구글 시트면 사람에게 CSV로 내보내 달라고 하거나, 이미 내보낸 파일 경로를 받는다.

## 2. 점검 실행
스크립트는 이 SKILL.md가 있는 폴더의 `scripts/` 안에 있다. 전체 경로로 실행한다.
- 명령은 `&&`·`;`로 묶지 말고 **하나씩** 실행한다. 묶으면 권한 확인에서 한꺼번에 거부될 수 있다.
```bash
python3 /…/scripts/check_contacts.py <파일.csv> --out <문제목록.csv> [--required 회사명,이메일,출처] [--stale-days 90]
```
- 칸 이름이 달라 못 알아보면 출력의 "알아본 칸"을 보고 `--required`에 실제 칸 이름을 넣어 다시 돌린다.

## 3. 결과 정리
스크립트의 표를 그대로 옮기고, 그 아래에 사람이 할 일을 우선순위로 적는다.
1. **메일을 막아야 하는 것**: 중복 이메일(두 번 발송 위험), 이메일 형식 오류
2. **합칠 후보**: 같은 회사 다른 표기 → 어느 표기로 통일할지 제안
3. **채울 것**: 누락 칸, 출처 없는 행 (출처 없는 연락처는 쓰지 않는 것을 권장)
4. **다시 확인할 것**: 오래된 정보, 개인 휴대폰 의심 번호(공개된 업무용 연락처인지)

사람이 저장 위치를 정했으면 그 파일로 보고서를 쓴다.
